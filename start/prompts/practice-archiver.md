# 实践归档（Muse；我说"结束"时，或实践任务的机器验收全部通过时）

只归档**实践线**（环境任务按 `setup.md` 归档），只改下面列出的文件。给别人看的部分必须精简（预算见 `start/RULES.md` §1）。

## 同步清单
1. 开始写之前 `git pull --rebase`，避免覆盖 GPT 刚推送的理论线改动。
2. `journey/practice/log.md` 追加 1 行（≤ 120 字）：`日期 | 实际用时 | 任务ID | 做了什么 | 机器验收: ✓/✗/未跑 | 卡点`。用时问我；任务 ID 用完整形式（如 `I1-P03`）。
3. `campaign.md` **实践线表**中该任务的状态：第一次实践 → `进行中`；机器验收全部 ✓ → `通过`（实践线不设考官）。
4. `start/STATE.md` 中**只改"实践线"小节**：当前实践任务、上次停在哪、下一步。
5. 任务通过时：
   - `results/` 中放好代码、testbench、脚本和报告；实验或模块的 README 按 `start/templates/experiment-readme.md` 写（≤ 30 行）
   - `results/README.md` 的结论表（`<!-- results:start -->` 与 `<!-- results:end -->` 之间）加一行；首页成果表由脚本生成，不直接改首页
   - `journey/README.md` 时间线加一行
   - STATE 指向下一个实践任务；任务卡不存在就在"下一步"写"下次开始时起草"
6. 用时检查：本战役实践线已用时超过已通过和当前实践任务计划用时之和的 1.5 倍时，在 STATE 实践线小节写一行提醒，不替我砍。
7. **战役结束时**（两条线的必做任务都"通过"，或到了截止日）：`start/ROADMAP.md` 中该战役状态改为 `完成`，按 `campaign.md` 的收尾定义打 tag，时间线加一行，STATE 顶部指向下一个战役。
8. 运行 `python start/scripts/progress.py` 直到全部 ✓。
9. 分开提交：我写的代码用 `[me] <一句话>`，其余用 `[ai] 实践归档：<任务ID> <一句话>`；推送前再 `git pull --rebase`，有冲突时只保留双方各自的小节，README 的进度块重新运行 progress.py 生成。
10. 用 2–3 行告诉我：改了什么、两条进度条现在是多少、下次实践从哪里开始。

## 写作规则
- 数字从工具输出原样复制，不编造；不写免责句；局限每个模块最多 3 条，只写在它 README 的"边界"一节。
- 不改理论线的文件（`journey/theory/`、理论线任务卡和 STATE 小节）、不改验收条件、不新建规则或计划。
