# 理论归档（GPT；我说"结束"时，或处理 Gemini 判定时）

只归档**理论线**，只改下面列出的文件。给别人看的部分必须精简（预算见 `start/RULES.md` §1）。

## 同步清单
1. 开始写之前 `git pull --rebase`，避免覆盖 Muse 刚推送的实践线改动。
2. `journey/theory/log.md` 追加 1 行（≤ 120 字）：`日期 | 实际用时 | 任务ID | 做了什么 | 机器验收: ✓/✗ | 闭卷: ✓/未做 | 考官: 通过/不通过/未考 | 卡点`。用时问我；任务 ID 用完整形式（如 `I1-T03`）；读过的导读编号写进"做了什么"。
3. `campaign.md` **理论线表**中该任务的状态：第一次学习 → `进行中`；机器验收全部 ✓ → `待考官`；Gemini 判定通过，或任务卡写明"不考官"且机器验收全部 ✓ → `通过`；判定不通过 → 保持 `待考官`，把"补："的内容写进 STATE。
4. `start/STATE.md` 中**只改"理论线"小节**：当前理论任务、上次停在哪、未解决的问题、下一步。
5. 我在学习中用自己的话说清楚的理解，写进 `journey/theory/notes/<主题>.md`（≤ 1 页，同主题追加）。没有就不写。
6. 任务通过时：`journey/README.md` 时间线加一行；STATE 指向下一个理论任务，任务卡不存在就在"下一步"写"下次开始时起草"。
7. 用时检查：本战役理论线已用时超过已通过和当前理论任务计划用时之和的 1.5 倍时，在 STATE 理论线小节写一行提醒，不替我砍。
8. 运行 `python start/scripts/progress.py` 直到全部 ✓。
9. 用 `[ai] 理论归档：<任务ID> <一句话>` 提交；推送前再 `git pull --rebase`，有冲突时只保留双方各自的小节，README 的进度块重新运行 progress.py 生成。
10. 用 2–3 行告诉我：改了什么、两条进度条现在是多少、下次理论学习从哪里开始。

## 写作规则
- 只写事实，不编造用时和分数；不写免责句；新文件用英文短横线命名。
- 不改实践线的文件（`journey/practice/`、`results/`、实践线任务卡和 STATE 小节）、不改验收条件、不新建规则或计划。
